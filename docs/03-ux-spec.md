# PantryChef — UX-спецификация

Информационная архитектура, экраны и потоки. Это документ про **структуру и логику интерфейса**, без кода. Визуальное направление — «Тёплая кухня», см. прототип `pantrychef-prototype-v3.html` в корне проекта.

Принятые решения опираются на: [концепцию](./01-concept.md) (принципы 1–7) и [карту функций](./02-feature-map.md) (первая волна = Must, вторая = Should, помечено).

---

## 1. Информационная архитектура

### 1.1 Навигация: пять вкладок

```
┌──────────┬──────────────┬──────────┬──────────┬──────────┐
│  ГЛАВНАЯ │  ХОЛОДИЛЬНИК │  РЕЦЕПТЫ │   ПЛАН   │  ПРОФИЛЬ │
│ «Сегодня»│  (инвентарь) │          │ + покупки│          │
└──────────┴──────────────┴──────────┴──────────┴──────────┘
```

| Вкладка | Суть | Почему так |
|---|---|---|
| **Главная («Сегодня»)** | Дружелюбный дашборд: приветствие, быстрые действия, дайджест «Спасаем», три идеи, сводка холодильника | Человек открывает приложение не «в базу», а за ответом «что сегодня». Дашборд тёплый и персональный, но каждая цифра на нём — из живого холодильника |
| **Холодильник** | Полный инвентарь: группы, фильтры, правки, скан | Рабочий инструмент без украшательств — здесь наводят порядок |
| **Рецепты** | Идеи, поиск, избранное | Всё про блюда — в одном месте |
| **План** | План недели и список покупок (переключатель сверху) | План порождает покупки — им естественно жить вместе |
| **Профиль** | Аккаунт, статистика, настройки | Традиционно последняя |

**Главная ≠ лента.** На дашборде нет бесконечных списков и «контента»: пять блоков сверху вниз, каждый отвечает на один вопрос — «что просит внимания?», «что приготовить?», «что в холодильнике?», «что купить?». Каждый блок ведёт в соответствующий раздел.

**Решение: сканер — не вкладка и не FAB.** Скан — режим ввода, а не «место»: он живёт в быстрых действиях на Главной и в шапке Холодильника. Постоянная кнопка в таб-баре простаивала бы 6 дней из 7 и крала внимание на всех экранах.

**Решение: покупки — не вкладка, а сегмент внутри «Плана».** Список покупок — временный артефакт, а не постоянное место. В магазине до него два тапа: План → Покупки; плюс прямые входы (см. 1.2) и бейдж с числом позиций на вкладке, пока список непуст.

### 1.2 Глобальные точки входа (доступны отовсюду)

| Точка входа | Где видна | Куда ведёт |
|---|---|---|
| Сканер / «Добавить продукт» | Быстрые действия Главной, шапка Холодильника, пустые состояния, итог закупки | Сканер / быстрый ввод |
| Список покупок | Вкладка План (сегмент), карточка рецепта («добавить недостающее»), Главная (строка «Список покупок»), пуш | Список покупок |
| Уведомления | Колокольчик в шапке Главной | Лента уведомлений |
| Идеи и «Спасаем» | Пуш «Спасаем» → Главная | Соответствующий блок |

### 1.3 Стек навигации (глубина)

Глубина не больше трёх уровней от любой вкладки. Полноэкранные режимы (сканер, готовка) — модальные, без таб-бара: в них нельзя «сбежать» случайно.

## 2. Словарь интерфейса

Единые термины и состояния — используются во всех экранах и текстах.

### 2.1 Статусы свежести

| Статус | Условие | Смысл для пользователя |
|---|---|---|
| **Свежо** | срок > 3 дней | Спокойно, ничего делать не надо |
| **Скоро** | срок 2–3 дня | «На заметку»: стоит использовать в ближайших блюдах |
| **Спасаем** | срок сегодня или завтра | Требует действия: приготовить / заморозить / съесть |
| **Просрочено** | срок прошёл | Показываем «N дней назад»; при визите мягко спрашиваем, что с ним стало |

Порог «Спасаем» фиксирован (сегодня–завтра) — настраиваемость здесь ложная сложность.

### 2.2 Места хранения

Холодильник / Морозилка / Кладовая — три значения по умолчанию (полки и зоны — Could C12).

### 2.3 Категории продуктов

Овощи · Фрукты · Мясо и птица · Рыба · Молочное · Яйца · Бакалея · Заморозка · Напитки · Другое. Используются для группировки холодильника и отделов списка покупок. AI подставляет категорию автоматически, пользователь может поменять.

### 2.4 Причины списания

Приготовлено · Выброшено · Съедено как есть · Заморожено (остаётся в системе). Причины питают статистику S10, поэтому собираются с первого дня, но показываются только в статистике — пользователя не грузим.

### 2.5 Тон текстов (мини-справка)

Пишем как друг-повар: «У сметаны остался день — используем её в деле?», «Три продукта просят внимания», «Не получилось распознать полки. Попробуем ещё раз или добавим руками?». Никаких капса, восклицательных знаков-пачек и канцелярита.

## 4. Экраны подробно

### 01. Welcome

**Цель:** за 5 секунд объяснить суть и дать войти.
**Структура:** логотип (фирменный знак из `public/logo`) → крупный заголовок («Кухня, которая знает, что приготовить») → три строчки ценности: «Видит, что у вас в холодильнике · Подсказывает ужин без раздумий · Напоминает, пока продукт не пропал» → кнопки: «Начать» (primary) и «У меня есть аккаунт» (secondary).
**Состояния:** одно.

### 02. Вход

**Цель:** минимальное трение до аккаунта (данные должны синхронизироваться).
**Структура:** бренд-строка (логотип + имя) → «С возвращением» и подпись → поля email и пароль (с показом/скрытием) → строка «Запомнить меня» + «Забыли пароль?» → «Войти» → разделитель «или» → вход через провайдеров → «Нет аккаунта? Создать».
**Состояния:** ошибки полей — инлайн под полем человеческим языком; ошибка сети — баннер с «повторить»; при включённой 2FA — переход на 04.

### 03. Регистрация

**Цель:** создать аккаунт, не напугав формой.
**Структура:** назад → «Создадим аккаунт» и подпись → поля: имя, email, пароль → подпись о данных («Холодильник, план и покупки синхронизируются между вашими устройствами») → «Создать аккаунт» → «Уже есть аккаунт? Войти».
**Состояния:** инлайн-валидация; пароль < 8 символов — подсказка сразу, а не после отправки.

### 04. Код 2FA

**Цель:** подтвердить личность без нервов.
**Структура:** назад → знак-замок → «Код подтверждения» → подпись «Отправили на anna@…» → шесть ячеек OTP → таймер повторной отправки → «Подтвердить».
**Состояния:** автопереход фокуса; неверный код — мягкая встряска и понятный текст; успех — сразу дальше.

### 05. Онбординг: разрешения

**Цель:** получить камеру и уведомления, объясняя зачем каждое (принцип 5: уведомление = действие).
**Структура:** «Настройте PantryChef под себя» → две карточки: **Камера** («Для сканера штрих-кодов и фото полок — продукты появятся сами») и **Уведомления** («Скажем, что спасаем, до того как станет поздно») с кнопками «Включить» → «Продолжить» → «Пока не сейчас» (мелко).
**Состояния:** отказ — двигаемся дальше, ничего не блокируем; включённое разрешение отмечается галочкой на карточке.

### 06. Первый шаг: наполнение холодильника

**Цель:** довести до вау-момента — «из вашего холодильника уже есть идеи».
**Структура:** назад → «Наполним холодильник» → мягкая иллюстрация-сцена (камера + плавающие продукты) → два пути: «Сфотографировать полки» (primary, требует S2; до его реализации — скрыт, не задизейблен) и «Добавить по одному» (secondary) → «Позже» (мелко; подпись: «Без продуктов идеи будут случайными»).
**Дальше:** как только в холодильнике ≥ 3 продукта → авто-переход на Главную с готовыми идеями. Это и есть онбординг-вау.

### 07. Главная «Сегодня»

**Цель:** в одно открытие ответить: что просит внимания, что приготовить, что дома, что купить. Тёплый дашборд, а не лента.

**Структура сверху вниз:**

1. **Шапка.** «Привет, Анна» + дата («Четверг, 9 октября»). Справа: колокольчик (с точкой непрочитанных) и аватар (→ профиль).
2. **Дайджест «Спасаем сегодня»** — если есть «Спасаем»/«Просрочено». Карточка: «3 продукта просят внимания», чипы (сметана · черри · зелень), кнопка «Что с ними сделать?». Тап → список спасаемого в Холодильнике с предвыбранным фильтром.
3. **Быстрые действия** — четыре плитки: Сканер · Добавить · Идеи ужина · План недели. Одно нажатие = одно частое действие.
4. **«Что приготовить сегодня»** — три идеи-карточки: фото, название, время, «использует 6 из 7 ваших», бейдж «спасает сметану», кнопка «обновить» у каждой (перегенерация одной идеи). Ниже — «Все рецепты →».
5. **Сводка «Холодильник»** — компактная карточка: «21 продукт» и три цифры: 3 спасаем (терракота), 2 скоро (янтарь), 16 свежо (шалфей). Тап по цифре → Холодильник с этим фильтром; тап по карточке → весь список.
6. **«Список покупок»** — строка-ссылка: корзина, «Список покупок», «7 позиций →». Показывается только когда список непуст.

**Состояния:**
- *Холодильник пуст (после онбординга «позже»):* блоки 2 и 4–5 заменяются одной карточкой «Наполним холодильник» с быстрыми действиями скана и ввода.
- *Мало продуктов (< 3):* вместо трёх идей — «Добавьте ещё немного — и предложу ужин» + «Добавить».
- *Загрузка идей:* скелетоны на месте карточек.
- *Ошибка идей:* «Не получилось придумать. Попробуем ещё раз?» + кнопка.

### 08. Холодильник (инвентарь)

**Цель:** рабочая база: посмотреть, найти, поправить, добавить.

**Структура:**
1. **Шапка.** «Холодильник» + резюме («21 продукт · 3 спасаем»). Справа: «Сканер» и «Добавить».
2. **Полоска «Спасаем»** (если есть) — тонкая строка-ссылка с иконкой: «3 продукта просят внимания →» (дублирует дайджест Главной для тех, кто пришёл сразу сюда).
3. **Поиск по продуктам.** Из него же — переход к рецептам, если ничего не найдено: «Нет такого продукта. Найти рецепты с ним?»
4. **Чипы фильтров:** Все · Спасаем · Скоро · Просрочено · затем категории.
5. **Список** по категориям. Строка: мини-иконка категории → название → точечный лидер → количество → бейдж свежести со сроком.
6. **Действия со строкой:** свайп влево — списать (с причиной), свайп вправо — использовать (идеи с этим продуктом). Тап — карточка продукта (11).

**Состояния:** пусто (09); загрузка — кэш не блокирует скролл; ошибка сети — баннер с «повторить», список из кэша с пометкой.

### 09. Холодильник: пусто

Иллюстрация, «Холодильник пуст. Это легко исправить», кнопки «Сфотографировать полки» и «Добавить вручную». Один тон, два конкретных пути, без чувства вины.

### 10. Быстрый ввод продукта

**Цель:** продукт в системе за 5 секунд (M2).
**Структура (нижний модал):** «Добавить продукт» → поле «Что добавляем?» с автодополнением по недавним → как только выбрано: AI подставляет категорию, типичный срок («ср, 8 окт · типичный»), единицу → степпер количества → «Добавить ещё» (модал остаётся открытым, фокус в поле) и «Готово».
**Ключевое правило:** ничего не обязательно. Можно добавить только название — остальное додумает система и позже легко правится.

### 11. Карточка продукта

**Цель:** посмотреть и поправить конкретный продукт.
**Структура (нижний модал):** название + текущий бейдж свежести → строки: категория, количество (степпер), срок (дата-пикер + «типичный для категории»), место хранения (сегменты: Холодильник/Морозилка/Кладовая), заметка (опционально).
**Действия:** «Использовать» (идеи с этим продуктом), «Заморозить» (S7), «Списать» → причины (2.4), «Сохранить».
**Состояния:** просрочен — мягкий баннер «Просрочен 2 дня назад. Выбросим?» с действием.

### 12. Сканер

**Цель:** положить продукты без набора текста (S1, S2).
**Структура (полноэкранный, без таб-бара):** вид камеры → переключатель «Штрих-код / Фото полок» → рамка прицела → подпись-подсказка → кнопка затвора.
**Состояния:** нет доступа к камере — экран с объяснением и путём в настройки; распознавание — пульсирующая рамка; слабый свет — подсказка «Темновато, включите свет».

### 13. Результаты фото-скана

**Цель:** подтвердить распознанное за один экран.
**Структура:** «Нашли 6 продуктов» + «Переснять» → сетка карточек: название (редактируемое), уверенность, чекбокс → «Добавить выбранное (5)» → «Ничего не добавлять».
**Правило:** сомнительные распознавания сняты с выбора и помечены «уточните» — пользователь решает, а не исправляет молчаливые ошибки.

### 14. Рецепты (вкладка)

**Цель:** от «три идеи на сегодня» до осознанного поиска.
**Структура:**
1. Сегменты: **«Из холодильника»** (по умолчанию) / «Поиск» / «Избранное» (S8).
2. «Из холодильника»: три идеи на сегодня (те же, что на Главной) → фильтры-чипы (время, порции, кухня, вегетарианское) → «Остальное из ваших продуктов»: лента по покрытию ваших продуктов; у карточек — «использует 6 из 7» и «не хватает: сметана → в покупки».
**Состояния:** мало продуктов — предложение добавить; пустой результат фильтров — «Ничего с такими фильтрами. Сбросить?»

### 15. Поиск и фильтры рецептов

**Цель:** найти конкретное, когда оно известно.
**Структура:** строка поиска (предзаполнена переходом) → фильтры (время, порции, кухня, диета — C5) → результаты; поиск идёт и по рецептам, и по продуктам («курица» → блюда с курицей).
**Состояния:** пустой результат — с вариантами сброса фильтров.

### 16. Карточка рецепта

**Цель:** всё, чтобы решиться и начать.
**Структура:** фото во всю ширину → назад и «в избранное» поверх фото → название, время, порции, сложность → объяснение AI («Готовим, потому что у вас истекают черри, а курица ждёт со вчерашней закупки») → табы **«Ингредиенты» / «Шаги»**: ингредиенты строками «как чек» с отметками «есть» и «нет» (+ «в покупки»), шаги — компактно, полные — в режиме готовки → действия: «Готовить» (primary), «Запланировать на…» (S3).
**Состояния:** генерация — скелетон с честным статусом; ошибка — повтор.

### 17. Готовка

**Цель:** держать руку на рецепте, не пачкая экран.
**Структура (полноэкранный, экран не гаснет):** «Шаг 3 из 8» и закрыть → сегментный прогресс → крупный текст шага → если в шаге время — встроенный таймер-пилюля (тап → старт, звонок) → снизу: «Назад» и «Готово →».
**Правила:** шаги листаются свободно; таймеры продолжают тикать при переходах.

### 18. Списание после готовки

**Цель:** закрыть готовку — и обновить холодильник (M7).
**Структура:** «Что использовали?» + подпись «Отметьте — спишем из холодильника сами» → список ингредиентов «как чек», всё отмечено по умолчанию → заметка-итог («Холодильник обновится сам…») → «Списать и завершить» (причины собираются автоматически: приготовлено) → «Готовить снова когда-нибудь».
**Правило:** немаркированные позиции (соль, масло «по вкусу») не списываются по количеству, а помечают рецепт как «использованный».

### 19. План недели

**Цель:** снять решения разом (S3, S4).
**Структура:** переключатель «План / Покупки» → рельса дней (Пн–Вс, сегодня подсвечен) → сетка дня: слот «Обед» (если включён) и слот «Ужин» — карточка блюда или пустой слот «+ Добавить» → герой-карточка «Заполнить неделю из холодильника» (генерация с приоритетом скоропортящегося) → строка «Список покупок на неделю: 14 позиций →».
**Действия:** тап по карточке → рецепт; свайп → заменить или убрать; «Перенести на другой день».
**Состояния:** план пуст — герой-кнопка; генерация — плейсхолдеры по слотам.

### 20. Выбор блюда в слот

**Цель:** заполнить слот осознанно.
**Структура:** «Ужин · четверг» → группы: «Предлагаем на этот день» (учёт сроков продуктов **к этому дню** — это ядро ценности плана), «Из избранного», «Найти» (→ 15).

### 21. Список покупок

**Цель:** в магазине за минимальные тапы.
**Структура:** сегмент «План / Покупки» → карточка прогресса «Отметили 3 из 8» → позиции по отделам (2.3): чекбокс, название, точечный лидер, количество → поле «Добавить своё».
**Действия:** тап по чекбоксу — куплено (уходит вниз, приглушается); свайп — удалить; по завершении → 22.
**Состояния:** пусто — «Список пуст. Добавьте недостающее из рецепта или впишите руками».

### 22. Итог закупки

**Цель:** из «купили» — в «есть дома» (S6).
**Структура:** «Купили! Добавим в холодильник с типичными сроками» → список купленного: название, категория-чип, «≈ N дней» (правится тапом) → подсказка про типичные сроки → «Добавить всё в холодильник» → «Позже».
**Правило:** отмеченные «куплено» попадают сюда автоматически; невыбранные остаются в списке на следующий раз.

### 23. Профиль

**Цель:** лицо пользователя и зеркало кухни.
**Структура:** аватар, имя, email → сетка статистики (S10): «Приготовлено · Спасено · Выброшено (честно) · Серия дней» → карточка-факт («В этом месяце выброшено на 87% меньше…») → строки: Уведомления (счётчик включённых), Настройки, Помощь, Выйти.

### 24. Настройки

**Структура:** группы:
- **Кухня:** едоков дома (S9), обед в плане (вкл/выкл), диеты и аллергии (C5, помечено «скоро»);
- **Уведомления:** «Спасаем» по утрам, план на неделю, время напоминания;
- **Аккаунт:** двухфакторная защита, выйти.

### 25. Уведомления

**Структура:** лента по датам («Сегодня» / «Вчера»): строки — иконка с тоном события, заголовок, подпись, время (моно), точка непрочитанного. Типы: «Сметане остался день» (→ 11), «План на неделю пуст» (→ 19), «Список покупок: 7 позиций» (→ 21), «Рецепт сохранён» (→ 16). Сверху — «Прочитать все».

## 5. Потоки (сквозные сценарии)

### 5.1 Первый запуск → вау

Welcome (01) → вход или регистрация (02/03, при 2FA — 04) → разрешения (05) → наполнение холодильника (06): фото полок или 3 продукта вручную → Главная (07) с готовыми идеями. **Цель по времени: от «Начать» до первой идеи — меньше 2 минут.**

### 5.2 Ежедневный вечерний цикл

Пуш «Три продукта просят внимания» → Главная (07) → дайджест «Спасаем» → идея с бейджем «спасает сметану» → карточка рецепта (16) → «Готовить» → готовка (17) → списание (18) → холодильник обновлён. Чего не хватило → «в покупки» на 16.

### 5.3 Воскресная закупка

Вкладка «План» (19) пуста → «Заполнить неделю из холодильника» → план готов (правится через 20) → «Список покупок на неделю» (21) → в магазине отмечаем позиции → дома «Купили!» → итог закупки (22) → холодильник пополнен (08). Цикл замкнут без ручного набора.

### 5.4 Спасение одного продукта

Пуш или Главная (07) → карточка продукта (11) со статусом «Спасаем» → «Использовать» → идеи с этим продуктом в приоритете (14) → готовка (17) или заморозка. Три шага от тревоги к решению.

### 5.5 «Съел на бегу» (поддержание свежести данных)

Свайп по строке продукта в Холодильнике (08) → «съел яйцо» → минус одно. Без экранов и форм — так данные не протухают между готовками (S14).

## 6. Правила и закономерности

### 6.1 Политика push-уведомлений

| Тип | Когда | Частота |
|---|---|---|
| «Спасаем» | Утро; только если есть продукты «Спасаем»/«Просрочено» и есть, что предложить | максимум 1/день |
| «План пуст» | В день, выбранный пользователем для закупки (по умолчанию суббота), если план на неделю не заполнен | 1/неделя |
| «Покупки» | Только по явной просьбе пользователя («напомнить в магазине») | по запросу |

Никаких маркетинговых пушей. Каждый пуш ведёт на экран, где есть действие. Два подряд бесполезных пуши — повод пересмотреть правило, а не частоту.

### 6.2 Доступность и контекст кухни

- Минимальная зона касания — 44px: руки бывают мокрыми или в тесте.
- Ключевые состояния не кодируются только цветом: у бейджа свежести всегда текст («2 дня», «сегодня»).
- Контраст текста — по WCAG AA в обеих темах; «Спасаем» заметен в тёмной теме не только красным.
- Режим готовки: максимум контраста и размера, ноль анимаций без смысла, экран не гаснет.

### 6.3 Загрузки и ошибки

- Скелетоны — на месте будущего контента, не спиннер по центру.
- Ошибки AI — всегда с одним действием «повторить» и запасным путём («добавим руками»).
- Оптимистичные обновления для мелких действий (чекбокс, списание): интерфейс отвечает мгновенно, откат — тихий и с «вернуть».

### 6.4 Персональные данные и доверие

- Камера и уведомления запрашиваются в момент первой реальной потребности (онбординг, 05), с объяснением, а не при первом запуске залпом.
- Фото полок обрабатываются ради распознавания — формулировка в онбординге честная и короткая.

## 7. Что меняется относительно прошлых версий

Для преемственности — главные решения относительно первого прототипа (`pantrychef-prototype.html`) и ревизии v2 («Тихая кухня»):

| Было | Стало | Почему |
|---|---|---|
| v1: Главная = приветствие + одна карточка-подсказка; v2: Главная = сам холодильник | v3: Главная = дашборд «Сегодня»: приветствие, быстрые действия, дайджест «Спасаем», три идеи, сводка холодильника | Приложение открывают за ответом «что сегодня» — дашборд тёплый и быстрый; при этом каждая цифра на нём — из живого холодильника, так что принцип «холодильник — источник правды» не страдает |
| v1: 5 табов + FAB-сканер по центру таб-бара | 5 табов (Главная, Холодильник, Рецепты, План, Профиль), сканер — действие в быстрых действиях и шапке Холодильника | Скан — режим, а не место; центральный FAB крал внимание на всех экранах |
| v1: одна идея-подсказка без объяснения | Три идеи с выбором и объяснением «почему» | Принцип 3: выбор из трёх; принцип 6: AI объясняет |
| v1: «Спасаем» — баннер-предупреждение | Дайджест-карточка на Главной с чипами и действиями | Из уведомления о беде — в главный рабочий инструмент |
| Автосписание не показано | Готовка завершается экраном списания | «Данные не протухают» — условие выживания продукта |
| v1: покупки — отдельная вкладка | Сегмент внутри «Плана» + прямые входы + бейдж | Список — артефакт плана; вкладка простаивала бы |
| v2: приглушённый мох на фарфоре | Возврат к тёплой идентичности: мандарин на креме, дружелюбная Nunito, строгая 8pt-сетка | Аудитория просит близкий, тёплый тон — строгость переносим в сетку и систему, а не в холодный минимализм |
